# 网站维护说明

网站入口与本地预览见[项目首页](../README.md)。这里记录当前结构和维护规则。

## 页面与配置

| 文件或目录 | 用途 |
| --- | --- |
| `index.html`、`assets/app.js`、`assets/style.css` | 资讯、分类、搜索、收藏、汇率和房价 |
| `assets/archive.js` | 按需读取历史资讯，缓存已读分片 |
| `assets/personal.js` | 字号、已读标记与收藏备份 |
| `assets/editorial.js`、`assets/tonight.js` | 周末推荐与晚间安排 |

| `homes/`、`assets/home-finder.js` | 自动采集房源的筛选与变化记录 |

## 新闻

栏目为综合、财经、民生、科技、AI、模型、文娱、游戏和体育，另有汇率及杭州房价。去处从顶部独立进入。

- 每日速览从不同栏目和来源选择最多 10 条，合并同一事件的报道，不表示热度排名。
- 普通新闻按来源发布时间排列。原文入口优先使用已核实的发布方链接，未解析成功时保留原订阅链接。
- 历史保留最近 30 天、最多 6000 条，并为低频栏目和来源预留空间。实际覆盖天数取决于发稿量。
- 首次只读取最新 150 条及栏目摘要，搜索和翻页按需下载历史分片；不会让每次打开页面都下载完整归档。
- 再次打开先显示已缓存内容，再检查更新时间。更新失败保留可读内容，提供重试入口。
- 来源弹窗按需读取近 7 天的观察统计，可查看新增量、连接状况和重复比例。新增来源需要积累观察时间。

添加或替换来源时，修改 `sources.json`，确认分类、语言、原文链接和实际内容。聚合订阅与发布方官方 RSS 应明确区分。删除的来源会在后续归档合并时退出。

## 今晚与周末

“今晚”按到家时间和精力筛选，每次显示 3 个安排，可展开或换一组。晚到家只保留较短的居家玩法。内置玩法随页面提供，离线也能查看步骤；每天生成的主题过期后回到基础版本。

“周末”先展示新发现，常设地点折叠为备选，完整活动与地点目录在下方。目录的搜索和筛选不改变上方推荐。

- 补充检索计划每天北京时间 9 点、16 点执行，普通采集按小时检查。
- 新发现须有明确日期和来源。无法读取来源时不冒充核验成功，超过 48 小时未核实的活动不进入新推荐。
- 费用、预约、停车和用炉等条件只使用来源明确说明的内容。
- 推荐结合区域天气。旧预报标注时间，超过 48 小时不继续用于推荐；室外活动另需确认现场情况。
- “去过”“想去”“不感兴趣”会影响推荐，可撤销。今晚的常设玩法标为“玩过”后暂时避开，之后可再次出现。
- 反馈可先保存在当前设备；已连接的设备可共用记录，离线操作联网后重试同步。

## 汇率、房价与房源

汇率支持美元、日元、泰铢，方向统一为“1 单位外币折合人民币”。采集使用欧洲央行同日参考汇率交叉换算，保留最近 60 个自然日的有效报价，页面展示近 30 天。金额换算始终使用最新报价，不受图表日期选择影响。

30 天最低提醒以最新报价日为终点，达到或并列最低均高亮。历史不足、获取失败或报价超过 4 天时暂停提醒。页面明确区分参考汇率和实际兑换价格。

杭州房价区分统计期、来源发布日期和最近检查时间。旧报告不会被新的检查时间伪装成新价格；来源失败时保留已有报告。

房源从公开列表定时采集，支持预算、类型、区域和板块筛选，记录观察到的报价及状态变化。挂牌价、参考总价与估算值分别标注；列表中消失不能直接视为已售。覆盖范围和检查时间在页面内说明。

## 指南与小游戏

指南正文按章节下载，首屏正文随 HTML 提供；搜索、收藏、证据等级筛选和收藏导入导出均在浏览器中完成。上游内容的同步由 `scripts/sync_life_guide.py` 处理，保留正文版本及许可说明。

小游戏包含打砖块、飞机大战、跳跃跑酷、蜘蛛纸牌、数独、卡牌地牢、轻量塔防、俄罗斯方块、跳一跳、消消乐和扫雷。游戏按各自规则保存成绩或进度，准备好游戏页的离线资源后无需逐个打开下载。

## 离线与版本更新

页面及资源按版本配套缓存。正常刷新优先读取线上新页面，完成的新版本自动启用；已打开的游戏和阅读页面保留其资源，避免更新打断使用。

指南、小游戏、房源分别准备离线资源。显示“已准备好”后再断网；准备中断可以重试，已完成的章节不重复下载。Safari 普通标签页与主屏幕入口可能使用不同存储，需要在实际使用的入口完成准备。

离线可读的范围是已保存内容，原文链接和新数据仍需联网。浏览器清理站点数据后需要重新准备。

## 采集与发布

工作流为 `.github/workflows/news.yml`：

1. 检查数据处理规则和脚本语法。
2. 统一读取上一版完整快照。线上暂时不可用时使用最近通过检查的备份；两者都不可用则停止，避免丢失历史。
3. 各采集器复用同一快照，更新新闻、活动、地点、房价、汇率和房源，再整理摘要与推荐。
4. 同步指南，构建 `_site/`。代码推送还会执行完整浏览器检查。
5. 保留经过检查的数据备份，上传并发布 GitHub Pages。

定时任务计划每小时 17 分以及北京时间 9 点、16 点触发。任务串行执行，GitHub 调度可能延迟。手动刷新和自动补跑复用同一工作流。

`data/news.json` 是采集器使用的完整公开归档，`data/latest.json` 是首屏数据，`data/status.json` 仅包含更新时间。不要用首屏数据替换完整归档。

## 修改后检查

- 采集规则：`python3 -m unittest discover -s tests -v`。
- 页面或浏览器脚本：重新构建后运行 `tests/check-mobile.cjs`，命令见项目首页。
- 游戏规则：运行 `.github/workflows/news.yml` 中对应的 Node.js 单元检查。
- 云函数：[独立检查与发布说明](../ops/cloudflare/README.md)。

遇到问题先区分：数据来源、采集任务、Pages 发布、浏览器缓存。回滚代码通过 Git revert 完成，不清除用户的收藏、反馈或游戏存档。
