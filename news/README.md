# 资讯

综合热点 + AI/科技 + 模型发布 + 文娱 + 游戏 + 体育资讯门户。界面为原生 HTML/CSS/JavaScript；采集与构建仅需 Python 3.11+ 标准库，不需要模型 API 密钥。

## 本地运行

```sh
python -m unittest discover -s tests -v
python scripts/collect_news.py
python scripts/build_news.py
python -m http.server 8080 --directory _site
```

打开 http://localhost:8080 。要在远程服务器预览，优先绑定本机地址并通过 SSH 转发，不要开放开发服务器到公网。

## 内容和界面

- 48 个自动资讯来源（47 个 RSS 订阅及 1 个每日播报目录），详见 `sources.json`。综合为中国新闻网、中新网国际、中新网社会、中新网财经、德国之声中文、法国国际广播电台；科技与 AI 为 IT之家、爱范儿、Solidot、GitHub Blog、少数派、极客公园、雷峰网、量子位、Hugging Face、NVIDIA Blog、Google AI、Google DeepMind；文娱为中新网文娱、1905电影网、央视网文娱、澎湃文娱、国际在线文娱、新京报文娱、Variety、Deadline、Google 新闻·中文娱乐、The Hollywood Reporter、Billboard；体育为中新网体育、直播吧、虎扑体育、懂球帝、BBC Sport。
- 文娱和体育中标注“聚合”的 8 个订阅通过 Google 新闻 RSS 获取指定网站最近 7 天的简体报道，并非这些网站提供的官方 RSS；Google 新闻·中文娱乐为原有综合聚合源，杭州房市另有 3 个聚合订阅，见下文。模型栏目另有 4 个 Google 新闻聚合订阅及 1 个 OpenAI 官方 RSS，见下文；每日新盘播报直接读取住在杭州原站的发布日期和文章链接，其余使用发布方 RSS。中华网娱乐聚合因混入解梦、杂谈等内容替换为央视网文娱聚合；澎湃、新京报改为按标题检索文娱词，中文娱乐聚合在采集与历史合并时均校验文娱主题。文娱排除解梦和运势条目；体育排除彩经、赔率、投注推荐等推广内容，保留违规投注等纪律事件报道。移除了实际返回繁体标题的 BBC 中文、香港电台、中央社、Yahoo 台湾、明周、镜周刊与 KSD 各相关订阅，共 11 个，并按原分类补入 11 个。合并历史时仅保留当前配置的来源，移除源不会继续残留在公开归档中。
- “汇率”（`/#exchange`）放在杭州房价之前，支持美元 USD、日元 JPY、泰铢 THB 切换，方向均为“1 单位外币折合人民币”。`scripts/collect_exchange_rates.py` 在每次发布中获取欧洲央行官方 90 天 XML，三个币种共用一次下载，同日 `CNY/EUR ÷ 外币/EUR` 分别换算，保留最近 60 个自然日的有效报价，六位小数；这不是人民币中间价或银行柜台买卖价。完整快照成功后接受来源修订；请求失败、历史不足、重复日期或快照倒退时保留上次数据并标记不可用，不混用其他来源。首次已采集数据在 `news/exchange-rates.json`，发布结果嵌入 `exchangeRates` 与初始资讯一起离线保存；美元保留原结构以兼容旧缓存，日元、泰铢存放于 `currencies`，各币种失败独立保留旧数据。
- 汇率页面按所选币种独立判断最低价并展示最近 30 个自然日的已公布报价、响应式折线图、可拖动日期滑块和每日记录。最低提醒以最新报价日为终点，比较含当日在内 30 个自然日中的有效报价（不是 30 个交易日）；达到或并列最低都显示文字和金色边框。历史须覆盖区间起点且至少 15 个报价日，间隔不超过 5 天；无足够历史、异常数据、采集失败或最新报价距当前北京时间日期超过 4 天时不高亮。来源通常欧洲工作日每天发布一次，网站每次检查不代表新报价。核心计算在 `exchange-core.js`，已覆盖最低/并列/非最低/过期/缺失数据及离线浏览测试。
- “杭州房价”（`/#housing`）位于页签最右侧。首页分别展示新房成交均价、二手住宅网签均价，必须带明确统计周期、口径、来源链接；不使用挂牌价、参考价或四周移动均价替代。当前公开来源为中指云杭州周报、杭州网/潮新闻引用的杭州贝壳研究院月度统计，不能提供全市实时逐套成交。成交统计和楼盘报道均自动采集，不展示手工维护的小区成交样本、报价和房源卡片。
- `scripts/collect_housing_prices.py` 每次发布时检查中指云杭州报告目录、杭州网经济新闻目录及已收录原文。只解析白名单来源中措辞和时间明确的成交指标，按统计期排序，保留上次记录；没有新价格时不改统计日期。来源失败或措辞无法核实时显示状态；超过 45 天的统计另有提示。初始人工核实记录在 `news/housing-prices.json`。价格数据合入小型 `latest.json`，与新闻一起离线保存；打开成交价页不会请求新闻历史分片。
- 成交价页补充“官方房价走势”“各区新房成交”“克而瑞新房成交均价”。国家统计局从数据发布目录发现月度报告，只读取杭州新房/二手房两张总指数表的环比、同比指数，页面换算为涨跌幅；中指云读取区县表自身月份及十区成交套数、面积（万㎡）、金额（亿元），不把百城样本指数或挂牌价混入成交数据；克而瑞从浙江区域作者列表前两页发现月报，只解析明确月份的新房成交均价，单独展示其周期和口径。均随现有发布任务自动检查，失败保留上次数据，不以检查日期替代统计期；无可验证初始数据时隐藏该部分。数据在 `housingPrices.market`，来源状态在 `marketSources`，种子为首次公开页面采集结果。超过 75 天的补充数据另有提示。所有数据随初始资讯包离线保存，不增加浏览器的外站请求。
- 杭州房价页新增“楼盘与房市动态”，接入住在杭州原站“每日新盘播报”，只读取 `news_item` 中的文章标题、显式发布日期和本站每日播报链接；不依赖搜索索引及时收录，页面只给日期时按北京时间当日零点记录。潮新闻、杭州网、浙江在线的 3 个聚合订阅扩大检索楼盘、新盘、户型、预售、交房和样板房报道，仍要求标题含杭州/区县名称与房产词，并排除电影、票房、门票和股市等干扰。保留最近 30 天最多 120 条独立候选，构建时按标题去重，最多 60 条 `housingArticles` 随初始资讯离线保存，避免受最新 150 条和全局归档上限影响。默认显示 6 条，可继续展开，支持原文跳转与收藏；来源失败保留已收录报道。顶部提供住在杭州楼盘库、登记查询、房天下新房入口，以及跳转楼盘动态的按钮。楼盘资料与在售报价在原站查询，不混入成交均价；打开该页仍不下载历史分片。
- 支持 RSS 2.0 和 RSS 1.0/RDF。保留来源的原始语言，英文资讯不自动翻译。
- “模型”（`/#models`）位于 AI 页签后，收录国内外 AI 模型发布、版本升级与开放消息。新增 OpenAI 官方 RSS、Anthropic 与通义官方公告的 Google 新闻聚合，以及按标题检索国内/海外模型发布的中文媒体聚合（IT之家、量子位、机器之心、雷峰网）。Google DeepMind、量子位和其他现有来源中的模型发布同时归入此分类。通过标题中的模型名称/模型词与发布词筛选；排除发布传闻、应用/智能体功能更新及同名车辆等无关条目，可能因措辞遗漏。旧归档在每次采集合并时重分类。模型消息单独保留近 30 天候选（最多 120 条），不受普通新闻 6000 条上限挤占；`latest.json` 随附最近 60 条去重模型消息，列表按发布时间排列，打开栏目不扫描新闻历史分片，随首页离线缓存；支持来源、日期、搜索、收藏和分页。
- 首页默认进入每日速览。全部与分类按发布时间倒序，科技、AI 和模型页签分别展示各自分类，同一条资讯只归入一个分类。优先识别模型发布；股价、股票、财报等市场消息归综合，硬件/系统更新归科技，AI 工具、应用、研究、行业与监管归 AI。英文品牌词使用 ASCII 字母边界，支持紧邻中文的 AI/OpenAI 等词，并补入 Qoder/Cursor/Windsurf/Kiro 等工具名，避免漏判或把 AirPods/AION 当作 AI。专门的文娱、体育、杭州房市按本主题校验。历史合并重新应用当前来源配置和分类规则；标题识别仍可能遗漏。导航分阅读方式、新闻分类、数据与工具三个组，手机端阅读方式和工具在第一行，新闻分类在第二行，杭州房价保持最右侧。
- 每日速览默认显示北京时间当天的消息，轮流抽取综合/杭州房市/AI/模型/科技/文娱/游戏/体育，标题去重，尽量分散来源，最多 10 条。构建时将今天/昨天每类最多 5 条候选（最多 80 条）随 `latest.json` 发布为 `briefArticles` 与 `briefDays`，低频分类不再受最新 150 条的组成影响。默认今天和昨日速览无需扫描归档，离线也可阅读；其他日期或搜索/来源筛选仍按需读取归档。不是 AI 生成、编辑推荐或热度榜。
- RSS 摘要截取为不超过 90 字符的纯文本，不存储全文、不代理媒体图片。标题和链接保留原始来源。来源可按发布方要求从配置中移除。
- 来源缺少明确带时区的日期、日期过旧/过于超前、无安全 HTTP(S) 链接的条目不发布。
- 收藏将文章快照保存到当前浏览器的 localStorage，不会跨设备同步；浏览器拒绝持久化时会提示。
- 支持分类、来源筛选、关键词搜索、日期筛选、分页加载、深色模式、键盘搜索与 RSS。
- 打开页面先显示本浏览器上次成功保存的资讯，后台检查更新。已有数据时先读很小的 `status.json`，时间戳一致则不再下载新闻或重绘列表；有变化才下载最新 150 条，并保留当前分类、搜索和分页。状态文件不可用时回退直接读取新闻。新闻请求统一最多等 30 秒，有旧缓存时也自动重试一次，重试使用独立 URL 并绕过 HTTP 缓存；手动“重新连接”同样绕过失败缓存。失败保留当前列表，并区分超时、HTTP 状态、数据异常和离线提示。兼容不支持 `AbortSignal.timeout` 的浏览器，存储不可用也不影响在线读取。
- 构建生成 `data/latest.json`（最新 150 条、独立栏目候选及历史目录），保留每 150 条的旧格式归档供旧客户端读取。新读者使用按分类切分的每 100 条分片：来源、日期、分类筛选先读随首屏附带的轻量目录；关键词搜索先下载全站或当前分类的哈希索引，再只获取匹配分片，最多并发三份。输入停止 250 毫秒后发起历史查找。游戏不再受最近 60 条快照限制，低频来源可继续回看历史；来源下拉框只列当前分类中有已归档内容的来源。
- 最新资讯仍保存在 localStorage。历史分片和索引单独写入 `news-history-v1` CacheStorage，避免每批历史都序列化整份归档；同一版本重开时按需复用。保留当前版本与最近使用的其他文件，超过 120 份时清理较旧且不属当前版本的文件。存储不可用时仍可在线查询；离线仅能阅读已保存内容，缺失时给出提示。请求失败可重试，整批成功后才合并；切换筛选或刷新时不会将旧请求写入新数据。
- 相同标题的跨来源报道合并成一张卡片，“其他报道”中保留所有原文链接；Google 新闻标题末尾的发布方标签不参与合并，版本号和价格中的小数点仍保留。按来源筛选后再合并，不会隐藏指定来源；用户主动收藏的快照保持独立。
- 新闻列表与生活指南增加折叠的“阅读设置”，提供标准/较大/大号字号，设置在当前浏览器保留。新闻点击原文后标记已读，支持只看未读，最多保存 6000 个已读 ID。资讯收藏快照与指南收藏 ID 可一起导出 JSON，导入时合并并保留已有内容；损坏文件或不安全原文链接不会导入。没有账户或自动跨设备同步，迁移时在新设备手动导入文件。
- 首屏使用静态新闻占位、固定图标尺寸及更新状态区域；默认速览的日期和说明在 HTML 中已预留位置。后台检查提示在顶部状态区域替换显示，避免单独插入大块通知导致正文跳动。
- 游戏栏目在体育之前，接入机核、游研社、游民星空与 3DM 的 Google 新闻聚合，以及 Eurogamer RSS。最近 60 条快照加快首次打开，历史仍支持来源、日期、搜索和加载更多。
- “刷新资讯”通过 Cloudflare Worker 请求抓取和发布，完成后重新读取数据并保留当前筛选。全站共享至少 15 分钟触发间隔，已运行的任务会被复用；接口不可用时仍尝试读取 GitHub Pages 上已发布的数据。

## 安装与离线阅读（PWA）

页脚“安装到桌面”在浏览器允许时唤起原生安装窗口，否则展示对应平台操作。Chrome / Edge 可从地址栏或菜单安装，iPhone / iPad 可通过 Safari 分享菜单添加到主屏幕；支持的 Mac Safari 版本可添加到程序坞。安装需要 HTTPS（本地开发允许 localhost）；安装后的名称为“资讯”，以独立窗口打开。

- `/manifest.webmanifest` 提供名称、图标、启动路径和每日速览/收藏快捷入口。PNG 图标直接由现有 SVG 站点图标导出。
- `/sw.js` 首次只缓存新闻首页与启动资源；进入小游戏或生活指南后才分别准备其完整资源，首次联网完成后才能从该入口离线重新打开。文章、搜索和收藏使用本浏览器已保存的数据；不缓存或代理原文网站。小游戏页 `/games/` 与首页分别回退到各自匹配版本的缓存页面。
- 新闻 JSON、版本检查与刷新 API 不进入 Service Worker 缓存。联网时检查当前发布版本，检查期间先显示明确标记的本地数据；离线时直接阅读上次数据，恢复联网会重新检查资讯。手动刷新直接读取最新 150 条；历史在需要时继续补齐。首页完成首轮新闻请求后再注册离线资源，避免初次准备与新闻下载竞争网络；小游戏页仍立即准备。
- 首页与游戏导航优先返回已安装版本的缓存页面，避免离线启动等待网络、或在线 HTML 与旧脚本版本混用。安装阶段验证资源与 HTML 属于同一版本；不会将不存在的页面替换成新闻首页。
- 程序版本由 HTML、静态资源和 Service Worker 内容计算。只更新新闻不会更换程序缓存；程序改动安装完成后显示“更新页面”，用户点击后切换并清理本站旧缓存，保留收藏和其他应用缓存。
- 离线数据保存在本机，清除浏览器存储或浏览器回收空间后可能丢失；新闻更新和原文链接需要联网。PWA 本身不需要常驻服务器，也没有额外的后台抓取任务。

完成本地构建后，可用独立安装的 Playwright 运行完整安装/离线/更新检查：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright NEWS_TEST_SITE=_site node tests/pwa-browser.cjs
```

## 离线准备与恢复

- GitHub Pages 必须开启 `https_enforced`。2026-09-26 排查发现该设置原为 false，HTTP 地址直接返回页面，因不满足安全上下文条件而无法使用 Service Worker；现已开启，线上应验证 HTTP 返回 301 到 HTTPS。页面也为 `news.zacai.fun` 提供 HTTPS 跳转兜底，本地预览不受影响。
- iPhone 从桌面图标联网打开后，需要在这个入口完成离线准备。Safari 和桌面入口不能假定共享缓存；添加图标不等于已下载离线文件。旧 HTTP 图标若仍不可用，在 Safari 普通标签页用 `https://news.zacai.fun/games/` 重新添加图标，不要求清理浏览器数据。HTTP 与 HTTPS 是不同存储来源，不能保证旧 HTTP 存档自动迁移。
- 游戏列表新增“准备离线使用／重新检查”。资讯首页不显示游戏离线状态，也不主动执行游戏缓存检查或修复。安全连接缺失、离线接口不可用、缓存缺失、下载失败和等待更新分别提示，不再统称浏览器不支持。
- Service Worker 的 `CHECK_OFFLINE` 检查完整启动资源；`PREPARE_OFFLINE` 只补缺失文件，先核对 HTML 的哈希引用再写入，禁止把新 HTML 混入旧离线版本。不会清空 localStorage、注销 worker 或删除仍能使用的文件。游戏页前台恢复或重新联网会再次检查。
- 自动修复不等于永久保存；若系统已删除整个站点数据，仍需联网重新准备。未实际取得设备日志时，不把 HTTP 入口这一可复现配置缺陷断言为用户设备的唯一原因。

本地构建后的恢复测试（独立浏览器进程关闭后断网重开、完整性检查、缺失文件修复、存档保留、不安全／无接口环境提示）：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright NEWS_TEST_SITE=_site node tests/offline-recovery-browser.cjs
```

## 旧版 Safari 兼容

Safari 15.3 缺少原生 `<dialog>` 的 `showModal()` / `close()` 和 `Object.hasOwn()`（这些在 [Safari 15.4](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/) 加入）。前者曾让游戏路由初始化中断，并让未打开的弹窗混入布局；后者曾让 Service Worker 的导航与资源读取失败。

- `compat.js` 在业务脚本之前按能力检测，仅为缺少原生弹窗方法的浏览器提供遮罩、关闭、焦点约束与 Escape 处理；`compat.css` 显式隐藏未打开的弹窗。新闻来源、安装说明和游戏弹窗共用兼容处理。兼容资源参与哈希构建、离线缓存和更新。
- Service Worker 使用 `Object.prototype.hasOwnProperty.call()` 判断路径；游戏高度使用 `visualViewport` / `innerHeight` 的像素值，并以 `100vh` 作为 CSS 回退，不依赖新视口单位。
- 已安装旧版的用户需要联网打开页面，点“更新页面”，待小游戏列表显示“已准备好，可离线玩”后再断网。无需清空已有存档。

`node --test tests/sw-compat.cjs` 在没有 `Object.hasOwn` 的独立运行环境中验证离线导航、资源和路由范围。浏览器测试可加 `NEWS_LEGACY_SAFARI=1`，移除原生弹窗方法与新接口，覆盖初始化、触屏、弹窗、存档与离线更新；PWA 测试也会移除 Service Worker 中的新接口。这是缺失功能的回归测试，不等同于 iOS 15.3.1 真机测试。

## 离线小游戏

首页右上角“小游戏”进入 `/games/`，提供打砖块（五关）、飞机大战（自动开火、敌机逐渐加速）、跳跃跑酷（二段跳）。这三款采用原生 Canvas 实现，另有蜘蛛纸牌、数独、卡牌地牢、轻量塔防、俄罗斯方块、跳一跳、消消乐和扫雷，共十一款，均不加载第三方游戏、广告、字体或网络素材。

- 游戏页使用独立满屏布局，说明收进“玩法”。三款 Canvas 游戏画面随可见视口和安全区域适配，横竖屏保持物体比例；尺寸变化时暂停并调整当前局的位置，不清空成绩。
- 手机在画面任意位置相对拖动控制挡板和飞机，按下时不会跳到手指下方；点按跑酷跳跃。电脑可用方向键 / WASD，空格或 Enter 触发动作，P / Escape 暂停。
- 切换标签、应用或离开窗口自动暂停。返回后手动继续，避免后台继续扣机会。切换游戏开始新一局，最高分保存在 `zacai-arcade-records-v1`；存储受限时仍可玩并提示无法保存。
- 蜘蛛纸牌使用 104 张牌，支持单花色、双花色、合法走法提示、发牌和最近 30 步撤销。点选牌再点目标列移动，十列牌桌自适应屏幕宽度，手机竖屏也能看全；窄屏牌面将点数和花色上下排列，横屏牌面更大；随机洗牌不保证每局有解。
- 数独有入门、标准、进阶三档（分别 42、34、28 个已知数，难度按已知数区分，不是解题技巧评级）。九道自生成唯一解模板经过保解的行列、数字和转置变换生成题面；独立求解器测试唯一性。支持候选数笔记、重复数字标红、直接填一格答案的提示、擦除、撤销和键盘操作。
- 纸牌和数独分别在 `zacai-table-spider-v1` / `zacai-table-sudoku-v1` 自动保存当前局和最近 30 步，刷新、切换游戏后可继续。新一局需在难度对话框确认后才替换；损坏存档会回退新局，存储受限时明确提示只能在当前页面内保留。
- 卡牌地牢是原创的 12 层回合卡牌探索，含四类普通敌人、三个守门人、营地、商店与装备。每回合 3 点行动、抽 5 张牌；可搭配攻击、护盾、中毒、虚弱、治疗和强化。战利品加入本局牌组，装备提供持续加成；保存随机数状态及抽牌顺序，恢复时不重新洗牌。
- 轻量塔防是一张原创的 9×9 绕行地图，共 12 波，含快敌、装甲敌与首领。箭塔单体快攻、炮塔范围伤害、冰塔减速，每塔可升至 3 级；出售返还投入金币的 70%。支持战斗中建造、暂停、两倍速，并保存波次内的敌人位置。
- 俄罗斯方块使用 10×20 棋盘，七袋随机、三个后续预览、每块一次暂存、落点提示和旋转避墙。每消除 10 行加速；手机支持按钮长按、棋盘左右滑动、向下滑动和轻点旋转。电脑用方向键、空格落到底、C 暂存、P / Escape 暂停。
- 三款新游戏分别使用 `zacai-extra-dungeon-v1`、`zacai-extra-defense-v1`、`zacai-extra-blocks-v1` 存当前局，纪录存在 `zacai-extra-records-v1`。回合操作及时保存，实时游戏每两秒、落块或波次切换、暂停和离开时保存。恢复实时游戏后需要手动继续；尺寸变化也会暂停。存档会校验，存储受限时仍可在当前页面内切换后继续，并明确提示。
- 跳一跳通过长按画面或大按钮蓄力、松手起跳；电脑支持长按空格。落台得分，连续落在圆心有额外奖励，随进度缩小台面。切换页面、旋转屏幕自动暂停，未完成的蓄力会取消；已起跳的进度可保存并继续。场景显示当前台、下一台、后续两台和最近跳过的两台，落地后镜头平滑移动；后续平台写入存档并依次成为真实目标，旧版双平台存档会保留分数和当前跳跃后补全路线。
- 消消乐使用 7×7 棋盘，支持点选或滑动交换相邻方块，横竖三连消除和连锁倍数。每关 28 步，第一关目标 1000 分，后续每关增加 250 分。无效交换不扣步，提示免费，主动重排扣 2 步；无合法移动时自动免费重排。使用红圆、黄星、绿三角、蓝方块、紫十字、橙心形区分方块，放大轮廓并去掉阴影。消除只用静态描边提示，连锁一次呈现最终棋盘，取消反复缩放和闪淡；结算完成的状态在显示更新前保存，动画中退出也不会丢失分数。
- 扫雷有入门（8×8、10 雷）、标准（9×9、14 雷）、挑战（9×12、22 雷）三档。首次翻开及周围八格安全；支持长按、右键或 F 键插旗、明确的翻开/插旗模式，以及数字格周围旗数相符后的快速翻开。随机局面不保证无需猜测。计时只统计页面在前台、获得焦点且未打开弹窗的游玩时间；挑战棋盘在高度不足时可纵向滚动。
- 这三款新游戏使用 `zacai-casual-jump-v1`、`zacai-casual-match-v1`、`zacai-casual-mines-v1` 保存进度，跳一跳最高分使用 `zacai-jump-best-v1`。读档会校验，存储受限时提示并在当前页面内保留进度。新一局先确认，扫雷可在确认框选择难度。
- 全部游戏资源在进入小游戏后预缓存，不必先分别打开每一款。页面向正在控制它的 Service Worker 查询包括桌面启动首页、两张页面、manifest、图标及全部脚本样式的完整资源是否齐全，显示“已准备好，可离线玩”后可断网使用。浏览器清理缓存后需重新联网准备。
- 更新采用现有 PWA 的“更新页面”流程，首页与已准备过的小游戏/指南页面一起校验、一起切换；首次仅看资讯不会下载另外两个入口。小游戏不会触发新闻刷新 API。

## 自动发布

`.github/workflows/news.yml` 在 `hexo` 分支相关文件更新、手动执行以及每小时第 17 分钟运行。GitHub Pages 发布方式使用 GitHub Actions。代码推送在上传发布包前运行手机首屏、索引查找、收藏备份、旧格式兼容、PWA 更新、指南章节重试和小游戏冷启动恢复检查；按小时更新和手动刷新继续执行解析/保留规则检查，避免每次采集都重新安装浏览器。浏览器依赖锁定在 `tests/browser/package-lock.json`，可通过 `PLAYWRIGHT_MODULE=/path/to/playwright NEWS_TEST_SITE=_site node tests/check-mobile.cjs` 本地运行同一组检查。

构建从空目录生成资讯站，只发布资讯页面、小游戏、数据、RSS、站点地图和 PWA 资源。博客归档、历史文章和旧博客资源已下线，不再拉取旧博客快照；历史源码仍可从 Git 仓库中查阅。

采集时读取上次发布的 `/data/news.json`，合并去重，保留最近 30 天、最多 6000 条，历史随运行积累。达到上限时为每个分类预留最多 750 条，分类内将预留空间分散到来源，剩余位置按最新发布时间补齐；未用满的预留空间不浪费。实际覆盖天数取决于发稿量，不保证 30 天齐全；已清理的旧数据无法凭空恢复。单来源失败时保留其历史并显示不可用状态；所有来源失败则终止部署，线上保留上一个成功版本。页面分别显示最近检查时间和最新文章发布时间，超过两小时未检查会显示延迟提示。

GitHub 的计划任务不是严格实时调度，可能延迟或被跳过；公共仓库长期无活动时计划任务可能被禁用。可在 Actions 页面手动运行或重新启用。Cloudflare 每半小时检查一次停更并按条件补跑，配置见 [`ops/cloudflare/README.md`](../ops/cloudflare/README.md)；仍依赖 GitHub API 和执行队列可用，不保证严格准点。

每轮抓取的 Actions 日志包含逐来源 `SOURCE_METRIC`，记录检查时间、状态、有效条目数、新收录条目数及耗时；同样的数据写入 `news.json` 的来源状态。`newCount` 依据独立的观察历史计算：首轮建立基线，之后首次见到的有效条目计为新增，同源同日同标题的修订不重复计数。反复抓到旧文章、或文章被 6000 条归档上限清理后再次出现，都不会因此算新增。

“来源状态”提供近 7 个北京时间自然日的新增量、同标题跨源重复率、连续未新增天数，以及各日新增、重复和检查成功次数。支持分类、按新增/重复率/未新增时长排序，以及“只看需关注”。同标题按同一发布日比对，忽略空白及常见引号标点；仅 Google 新闻链接去掉末尾发布方标签，保留小数点和模型版本号。组内各源新增条目均计重复，后续发现其他源的同标题时会回填原观察日；不同标题的同一事件不计入。无新增时重复率显示横线，不显示 0%。至少新增 20 条且重复率达到 50%、连续 7 天未新增或本轮失败时标为需关注，低频官方源仍应结合发布周期判断。

质量统计从本功能上线开始积累，首轮不把现有归档冒充过去一周的统计。未新增时长以成功检查的连续观察时间为准，失败或间隔超过 3 小时后重新计时，失败次数单独记录。仅计入成功发布的采集轮次；所有来源失败时继续保留上次部署。调整某个来源的订阅地址、格式或分类会为该源重新建立基线，删除来源也会移除其统计。`sourceQualityState` 随采集器读取的完整 `/data/news.json` 保存，包含近 30 天资讯指纹和每日观察记录，独立于 6000 条正文归档；不会写入首页的小型 `latest.json`。公开汇总输出为 `/data/source-quality.<hash>.json`，只在打开来源弹窗时请求，最近查看过的同一版本可从本机缓存离线读取。汇总请求失败不影响资讯和连接状态，弹窗提供重试入口。继续使用原有 GitHub Actions 更新流程，无需新增服务器或模型 API。
