# 资讯云函数

云函数按时触发采集、协调刷新请求、检查停更，并同步去处记录。页面托管和资讯采集仍分别由 GitHub Pages、GitHub Actions 完成。

## 刷新流程

- 网页发起更新请求，云函数检查是否已有任务正在运行。
- 已有任务则返回该任务状态；没有任务且冷却结束时触发 `main` 上的 `news.yml`。
- 普通资讯刷新至少间隔 15 分钟，重复点击不会重复排队。
- 周末“重新找一批”使用 `scope: outings`，触发工作流的 `refresh_outings` 输入，强制检索活动、地点并重选推荐。它有独立的 15 分钟冷却，不因近期自动发布而跳过；有任务运行时返回忙碌，避免把普通采集误报为一次新的专题检索。
- 状态查询短暂缓存，上游异常时退避，避免连续请求。
- 主调度在每小时 17 分、北京时间 9 点与 16 点执行，触发前检查正在运行的任务和近期发布，避免重复排队；GitHub Actions 不再同时维护另一份定时调度。
- 停更检查在每小时 07、37 分执行。停更超过两小时、且没有近期或正在运行的任务时尝试补跑；同次停更在滚动 24 小时内最多补跑三次，两次至少间隔两小时。

这些时间是计划与触发限制，实际完成仍受 GitHub 队列和采集耗时影响。

## 去处记录

记录与刷新状态分别存储。普通网址和桌面安装版打开即可同步，记录按网站共用，不做访客身份区分。来源检查、请求频率、请求大小和字段校验仍生效；来源检查不等于身份验证。反馈按条目更新，支持撤销；浏览器离线时保留待同步操作，联网后重试。部署时保持现有存储绑定和实例名称，避免重建已有记录。

周末建议通过同一偏好接口单独更新，保留既有出发地、交通和反馈；清空建议也会留下修改时间，下一轮重新筛选。前端检索前等待待传操作完成，避免使用尚未同步的旧偏好。

积累文字通过独立接口读写，不进入推荐偏好的返回数据。每条记录单独保存，批量操作与回执一起原子写入；重试同一操作不会重复保存或恢复已删除内容。客户端按版本检查，无变化时省略正文；有变化时合并未提交操作。已有本机记录首次同步会合并，旧入口也会自动转回对应的普通页面。

## 本地检查

在本目录使用 Node.js 22 或更新版本执行：

```sh
npm ci
npm test
npm run check
```

测试覆盖触发冷却、并发请求、失败退避、目标分支、访问控制和记录同步，并使用 Miniflare 验证运行时及重启后的状态保留。`npm run check` 只检查打包结果。

## 发布与验证

完成当前环境的部署配置后，执行：

```sh
npm run deploy
```

云函数修改推送后会运行 `news-worker-check.yml`。网站发布工作流不代替云函数部署。

部署后确认状态接口正常、目标分支为 `main`，并观察一次完整更新从触发、采集到 Pages 发布的结果。回滚时恢复对应代码并重新部署，保留持久化存储。
