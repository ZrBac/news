# 资讯

综合热点 + AI/科技 + 模型发布 + 文娱 + 游戏 + 体育资讯门户。界面为原生 HTML/CSS/JavaScript；采集与构建仅需 Python 3.11+ 标准库，不需要模型 API 密钥。

## 本地运行

```sh
python -m unittest discover -s tests -v
python scripts/collect_news.py
python scripts/build_news.py
python -m http.server 8080 --directory _site
```

打开 http://localhost:8080 。要在远程服务器预览，优先绑定本机地址并通过 SSH 转发，不要开放开发服务器到公网。

## 内容和界面

- 55 个自动资讯来源（54 个 RSS 订阅及 1 个每日播报目录），详见 `sources.json`。综合为中国新闻网、中新网国际、中新网社会、德国之声中文、法国国际广播电台；财经为中新网财经、第一财经聚合、新华财经聚合；科技与 AI 为 IT之家、爱范儿、Solidot、GitHub Blog、少数派、极客公园、雷峰网、量子位、Hugging Face、NVIDIA Blog、Google AI、Google DeepMind；文娱为中新网文娱、1905电影网、央视网文娱、澎湃文娱、国际在线文娱、新京报文娱、凤凰娱乐、北京日报文娱、Google 新闻·中文娱乐、人民网文娱、新华网娱乐；体育为中新网体育、新华网体育、直播吧国内体育、虎扑国内篮球、懂球帝国内足球。
- 文娱和体育中标注“聚合”的 13 个订阅通过 Google 新闻 RSS 获取指定网站最近 7 天的简体报道，并非这些网站提供的官方 RSS；Google 新闻·中文娱乐为原有综合聚合源，杭州房市另有 3 个聚合订阅，见下文。模型栏目另有 4 个 Google 新闻聚合订阅及 1 个 OpenAI 官方 RSS，见下文；每日新盘播报直接读取住在杭州原站的发布日期和文章链接，其余使用发布方 RSS。文娱的 Variety、Deadline、The Hollywood Reporter、Billboard 四个英文来源分别替换为凤凰娱乐、北京日报文娱、人民网文娱、新华网娱乐，保持文娱 11 源，全站现为 55 源；凤凰与新华按娱乐频道检索，北京日报与人民网按标题筛选影视、音乐、演出等主题，随原有任务自动更新。中华网娱乐聚合因混入解梦、杂谈等内容替换为央视网文娱聚合；澎湃、新京报改为按标题检索文娱词，中文娱乐聚合在采集与历史合并时均校验文娱主题。文娱排除解梦和运势条目；体育排除彩经、赔率、投注推荐等推广内容，保留违规投注等纪律事件报道。移除了实际返回繁体标题的 BBC 中文、香港电台、中央社、Yahoo 台湾、明周、镜周刊与 KSD 各相关订阅，共 11 个，并按原分类补入 11 个。合并历史时仅保留当前配置的来源，移除源不会继续残留在公开归档中。
- “汇率”（`/#exchange`）放在杭州房价之前，支持美元 USD、日元 JPY、泰铢 THB 切换，方向均为“1 单位外币折合人民币”。`scripts/collect_exchange_rates.py` 在每次发布中获取欧洲央行官方 90 天 XML，三个币种共用一次下载，同日 `CNY/EUR ÷ 外币/EUR` 分别换算，保留最近 60 个自然日的有效报价，六位小数；这不是人民币中间价或银行柜台买卖价。完整快照成功后接受来源修订；请求失败、历史不足、重复日期或快照倒退时保留上次数据并标记不可用，不混用其他来源。首次已采集数据在 `news/exchange-rates.json`，发布结果嵌入 `exchangeRates` 与初始资讯一起离线保存；美元保留原结构以兼容旧缓存，日元、泰铢存放于 `currencies`，各币种失败独立保留旧数据。
- 汇率页面按所选币种独立判断最低价并展示最近 30 个自然日的已公布报价、响应式折线图、可拖动日期滑块和每日记录。最低提醒以最新报价日为终点，比较含当日在内 30 个自然日中的有效报价（不是 30 个交易日）；达到或并列最低都显示文字和金色边框。历史须覆盖区间起点且至少 15 个报价日，间隔不超过 5 天；无足够历史、异常数据、采集失败或最新报价距当前北京时间日期超过 4 天时不高亮。来源通常欧洲工作日每天发布一次，网站每次检查不代表新报价。核心计算在 `exchange-core.js`，已覆盖最低/并列/非最低/过期/缺失数据及离线浏览测试。
- “杭州房价”（`/#housing`）位于页签最右侧。首页分别展示新房成交均价、二手住宅网签均价，必须带明确统计周期、口径、来源链接；不使用挂牌价、参考价或四周移动均价替代。当前公开来源为中指云/克而瑞杭州周报、杭州网/潮新闻引用的杭州贝壳研究院月度统计，不能提供全市实时逐套成交。成交统计和楼盘报道均自动采集，不展示手工维护的小区成交样本、报价和房源卡片。
- `scripts/collect_housing_prices.py` 每次发布时检查中指云杭州报告目录、杭州网经济新闻目录及已收录原文。只解析白名单来源中措辞和时间明确的成交指标，按统计期排序，保留上次记录；没有新价格时不改统计日期。中指云周报不可获取或无法解析时，从克而瑞浙江区域前两页发现至多两篇公开周报，解析其城市新房摘要中明确的周度成交均价，补充来源、口径与周期，不拿土地、区域或单楼盘价格替代全市均价。来源失败显示状态；新房超过 14 天、二手房超过 45 天另有提示。页面区分最近检查时间和真实统计期，并说明周度/月度发布周期。初始人工核实记录在 `news/housing-prices.json`。价格数据合入小型 `latest.json`，与新闻一起离线保存；打开成交价页不会请求新闻历史分片。
- 成交价页补充“官方房价走势”“各区新房成交”“克而瑞新房成交均价”。国家统计局从数据发布目录发现月度报告，只读取杭州新房/二手房两张总指数表的环比、同比指数，页面换算为涨跌幅；中指云读取区县表自身月份及十区成交套数、面积（万㎡）、金额（亿元），不把百城样本指数或挂牌价混入成交数据；克而瑞从浙江区域作者列表最多四页发现月报，发现上个完整月的报告后提前结束，只解析明确月份的新房成交均价，支持“新房市场”和“商品住宅市场”标题及供应/成交合并表述，单独展示其周期和口径。均随现有发布任务自动检查，同一轮成功读取的页面复用，失败保留上次数据，不以检查日期替代统计期；无可验证初始数据时隐藏该部分。数据在 `housingPrices.market`，来源状态在 `marketSources`，种子为首次公开页面采集结果。克而瑞月报超过 45 天、其他补充数据超过 60 天另有提示。所有数据随初始资讯包离线保存，不增加浏览器的外站请求。
- 杭州房价页新增“楼盘与房市动态”，接入住在杭州原站“每日新盘播报”，只读取 `news_item` 中的文章标题、显式发布日期和本站每日播报链接；不依赖搜索索引及时收录，页面只给日期时按北京时间当日零点记录。潮新闻、杭州网、浙江在线的 3 个聚合订阅扩大检索楼盘、新盘、户型、预售、交房和样板房报道，仍要求标题含杭州/区县名称与房产词，并排除电影、票房、门票和股市等干扰。保留最近 30 天最多 120 条独立候选，构建时按标题去重，最多 60 条 `housingArticles` 随初始资讯离线保存，避免受最新 150 条和全局归档上限影响。默认显示 6 条，可继续展开，支持原文跳转与收藏；来源失败保留已收录报道。顶部提供住在杭州楼盘库、登记查询、房天下新房入口，以及跳转楼盘动态的按钮。楼盘资料与在售报价在原站查询，不混入成交均价；打开该页仍不下载历史分片。
- 体育以国内联赛、中国运动员与综合体育报道为主。BBC Sport 一对一替换为新华网体育聚合；直播吧筛选国内联赛和中国运动员，虎扑限定新闻频道的国内篮球，懂球帝筛选国内足球。三个专题源在采集和归档合并时都按标题校验国内联赛、国家队、中国选手及国内赛事线索，旧版集中收录的 NBA、欧洲足球和无关社区标题会按新规则移出；中国选手参加海外赛事的消息仍收录。中新网、新华网补充综合赛事和国际体育动态，保持体育 5 源，全站现为 55 源。标题识别可能遗漏措辞不明确的报道；更改专题范围时质量统计重新建立基线，只使用当前规则下保留的资讯作为参考。
- “去处”（`/#local`，保留原链接与收藏兼容）移至顶部，与生活指南、小游戏并列；不出现在新闻分类、每日速览、全部资讯和新闻侧栏中，独立视图隐藏新闻分类与侧栏。关注杭州市区及桐庐、临安、千岛湖、安吉、德清、海宁等周边的近期出游消息，分为市集节庆、展览演出、户外周边、亲子体验、城市漫游和运动观赛。包括音乐节、话剧、放映、读书会、公益讲座、非遗手作、研学、徒步骑行、赏花赏秋、采摘、温泉、桨板等，不限于固定活动名称。杭州网、潮新闻和五个专题聚合订阅（含露营）随新闻自动采集；专题检索限制到本地媒体、政府、新华网、人民网及本地宝等公开来源，过滤交通建设、招聘办事、行业规模、明星偶遇、活动回顾与批量 SEO 标题。已收录旧新闻按新规则重新分类，房市仍在杭州房价，社保就业等进入民生。
- `scripts/collect_weekend.py` 在每次发布时生成独立的 `weekendArticles`（最多48条）及 `weekendGuide`，首次接入或来源配置变更时补搜，每天北京时间9点和16点各执行一次当周末专题检索，周末照常，并使用 `0 1,8 * * *` 的 GitHub Actions 定时触发。原有来源仍每小时检查；若调度延迟，后续常规采集补做最近一次到期检索，跨日零点不额外重搜。同一时段成功时间从上次发布复用，避免每小时重复检索，全部失败会重试并保留上次结果。检索使用公开 Google 新闻 RSS 的主题、地点、日期关键词，无需模型 Key、常驻 Agent 或服务器，不覆盖所有社交平台。
- 出游采集复用原文链接，每轮最多补解析24条聚合地址（14秒调度预算），再以4路并行读取至多24篇原文（单篇7秒、1MB上限），24小时内已尝试的记录复用。只从明确的活动时间、展期、标题日期或正文中唯一的日期段提取时间；多场活动的不同日期不强行合并，只给结束日时不编造开始日。“本周末”按报道发表当周换算，不会每周重新变成当前日期。地点和费用也仅在原文明确标注时展示，未知日期标为“活动时间见原文”。默认隐藏已结束、取消、延期的活动，合并同名活动及原文链接；未定日期的消息保留10天，户外线索保留21天。“本周末”排除已知不在本周末的安排，可切换“近期安排”并按玩法、关键词、来源、消息发布日期筛选。采集快照与前端均按消息真实发布时间倒序，明确活动日期只参与周末/近期筛选和过期判断，不再将较早报道固定排在前面；上限48条与同活动/原文去重继续生效。前端会重排旧快照，在线、离线均不受旧排序影响，不以检查时间代替发布时间。独立快照随初始资讯保存，浏览栏目不下载新闻归档；收藏、备份及离线读取保留活动信息。
- 「去处」按偏好排除演唱会、歌友会及巡回演唱信息：7个本地订阅均添加搜索排除词，分类、专题快照和前端旧缓存再过滤标题，保留其他展览、话剧、音乐会与音乐节。已有主动收藏的文章不删除。新增杭州及周边露营专题源，随每小时来源检查及每天9点、16点专题补搜更新。
- 「露营去哪里」按用户偏好“停车后少量搬运、能用卡式炉做饭”整理风笑岭、路隐那森·中苕溪、安吉山海营及安吉野欢原4处营地。公开资料分别标注停车/车辆入营、装备运送与卡式炉条件，安吉地点明确标为杭州周边；野欢原普通车是否可到所选营位尚无明确资料，提示优先确认靠近停车区的位置，不把停车场或房车营位等同于普通车直达。附地图与公开资料链接，停车距离、自带炉具、日营及运送费用仍需按日期确认。仅在「去处」的全部/户外玩法下出现，支持关键词检索；不随活动日期、来源筛选。
- 「杭州爬山」收录宝石山、吴山、半山、玉皇山、北高峰、十里琅珰、径山古道、临平山、皋亭山及凤凰山10条路线；强度、预留时长为本站据公开资料整理的参考，非实时路况。「下雨去哪」移除博物馆与美术馆，改为香蕉攀岩、PARTYDAY运动乐园、冰纷万象滑冰、自然造物手作、天目里茑屋书店、杭州剧院话剧及浙江图书馆之江馆7处，分别说明预约、场次、费用等出发前需确认的条件，不把常设场馆当成每周固定活动。资料查阅日期2026-10-23。三组共21处地点，按玩法和关键词筛选，运动玩法也显示相应雨天去处；搜索匹配时自动展开，清空后恢复状态。计数区分地点参考与活动消息，静态资料不随活动日期、来源筛选，不宣称由活动采集自动维护；随PWA页面缓存离线可读，地图和资料页需联网。手机单列、桌面双列，不加载地图SDK或额外推荐接口。
- “民生”（`/#livelihood`）关注社保医保、补贴、就业、消费权益及实际谣言澄清，来源为新华网、央广网和中国互联网联合辟谣平台的聚合订阅。排除同名银行、证券机构、纯宣传活动、行业论坛及仅涉及海外的服务政策，不将“民生”二字本身作为主题依据。各地政策以原文的适用对象、区域和日期为准。
- “财经”（`/#finance`）位于综合之后，迁入中新网财经官方 RSS，新增第一财经、新华财经的 Google 新闻最近 7 天简体聚合，全站现为 55 源。财经关注经济政策、金融市场及企业经营，标题筛选股票、财报、营收、利率、汇率、央行等主题，排除开户送礼、稳赚荐股等推广，保留诈骗揭露与监管报道。模型发布仍优先进入模型；杭州房市、本地公共服务和全国民生权益优先归对应栏目，已收录的普通市场报道同步重分类。使用独立栏目索引，支持历史搜索、来源/日期筛选、收藏与已缓存列表的离线阅读。出游消息独立进入「去处」；每日速览在其余十类新闻中选取，最多 10 条。
- 手机端压缩更新时间和导航区域，完整来源状态仍可查询；日期选择默认收起，点击日期按钮展开。分类仅在导航自身横向滑动，不使整页横向溢出，选中远端栏目只调整导航横向位置。搜索、来源选择及日期输入使用 16px 字号；说明文字取消大块背景；Google 聚合标题中的重复发布方尾标及只复述标题的摘要在手机端隐藏，原始标题、摘要、链接和完整无障碍链接名仍保留，桌面展示继续使用原文。杭州、民生、财经收藏已补齐导出及导入校验。
- 支持 RSS 2.0 和 RSS 1.0/RDF。保留来源的原始语言，英文资讯不自动翻译。
- “模型”（`/#models`）位于 AI 页签后，收录国内外 AI 模型发布、版本升级与开放消息。新增 OpenAI 官方 RSS、Anthropic 与通义官方公告的 Google 新闻聚合，以及按标题检索国内/海外模型发布的中文媒体聚合（IT之家、量子位、机器之心、雷峰网）。Google DeepMind、量子位和其他现有来源中的模型发布同时归入此分类。通过标题中的模型名称/模型词与发布词筛选；排除发布传闻、应用/智能体功能更新及同名车辆等无关条目，可能因措辞遗漏。旧归档在每次采集合并时重分类。模型消息单独保留近 30 天候选（最多 120 条），不受普通新闻 6000 条上限挤占；`latest.json` 随附最近 60 条去重模型消息，列表按发布时间排列，打开栏目不扫描新闻历史分片，随首页离线缓存；支持来源、日期、搜索、收藏和分页。
- 首页默认进入每日速览。全部与分类按发布时间倒序，科技、AI 和模型页签分别展示各自分类，同一条资讯只归入一个分类。优先识别模型发布；股价、股票、财报等市场消息归财经，硬件/系统更新归科技，AI 工具、应用、研究、行业与监管归 AI。英文品牌词使用 ASCII 字母边界，支持紧邻中文的 AI/OpenAI 等词，并补入 Qoder/Cursor/Windsurf/Kiro 等工具名，避免漏判或把 AirPods/AION 当作 AI。杭州及周边的活动优先进入「去处」；其他文娱、体育、杭州房市按本主题校验。历史合并重新应用当前来源配置和分类规则；标题识别仍可能遗漏。导航分阅读方式、新闻分类、数据与工具三个组，手机端阅读方式和工具在首行，新闻分类使用一行可横向滑动的导航，选中的栏目自动滚入可见位置，杭州房价保持最右侧。
- 每日速览默认显示北京时间当天的消息，轮流抽取综合/财经/民生/科技/AI/模型/文娱/游戏/体育/杭州房市，标题去重，尽量分散来源，最多 10 条。构建时将今天/昨天每类最多 5 条候选（最多 100 条）随 `latest.json` 发布为 `briefArticles` 与 `briefDays`，低频分类不再受最新 150 条的组成影响。默认今天和昨日速览无需扫描归档，离线也可阅读；其他日期或搜索/来源筛选仍按需读取归档。不是 AI 生成、编辑推荐或热度榜。
- RSS 摘要截取为不超过 90 字符的纯文本，不存储全文、不代理媒体图片。标题和链接保留原始来源。来源可按发布方要求从配置中移除。
- 来源缺少明确带时区的日期、日期过旧/过于超前、无安全 HTTP(S) 链接的条目不发布。
- Google 聚合报道在采集阶段尝试解析发布方原文地址，保存为 `originalUrl`，原始 RSS 链接及据此生成的文章 ID 保留，避免改变收藏和已读记录。每次最多解析最近 100 个尚未解析的链接，4 路并行、35 秒调度预算、单请求最多 6 秒；已有解析结果从上次归档复用。解析依赖 Google 公开中转页的当前协议，失败或结果不合法时保留原聚合链接，不影响来源可用状态与资讯发布。网页、侧栏、其他报道及收藏优先使用合法原文地址；收藏备份与离线快照一并保留该地址。
- 收藏将文章快照保存到当前浏览器的 localStorage，不会跨设备同步；浏览器拒绝持久化时会提示。
- 支持分类、来源筛选、关键词搜索、日期筛选、分页加载、深色模式、键盘搜索与 RSS。
- 打开页面先显示本浏览器上次成功保存的资讯，后台检查更新。已有数据时先读很小的 `status.json`，时间戳一致则不再下载新闻或重绘列表；有变化才下载最新 150 条，并保留当前分类、搜索和分页。状态文件不可用时回退直接读取新闻。新闻请求统一最多等 30 秒，有旧缓存时也自动重试一次，重试使用独立 URL 并绕过 HTTP 缓存；手动“重新连接”同样绕过失败缓存。失败保留当前列表，并区分超时、HTTP 状态、数据异常和离线提示。兼容不支持 `AbortSignal.timeout` 的浏览器，存储不可用也不影响在线读取。
- 构建生成 `data/latest.json`（最新 150 条、独立栏目候选及历史目录），保留每 150 条的旧格式归档供旧客户端读取。新读者使用按分类切分的每 100 条分片：来源、日期、分类筛选先读随首屏附带的轻量目录；关键词搜索先下载全站或当前分类的哈希索引，再只获取匹配分片，最多并发三份。输入停止 250 毫秒后发起历史查找。游戏不再受最近 60 条快照限制，低频来源可继续回看历史；来源下拉框只列当前分类中有已归档内容的来源。
- 最新资讯仍保存在 localStorage。历史分片和索引单独写入 `news-history-v1` CacheStorage，避免每批历史都序列化整份归档，同一版本重开时按需复用。新闻检索和分页跳过出游分类的历史分片。保留当前版本与最近使用的其他文件，超过 120 份时清理较旧且不属当前版本的文件。存储不可用时仍可在线查询；离线仅能阅读已保存内容，缺失时给出提示。请求失败可重试，整批成功后才合并；切换筛选或刷新时不会将旧请求写入新数据。
- 相同标题的跨来源报道合并成一张卡片，“其他报道”中保留所有原文链接；Google 新闻标题末尾的发布方标签不参与合并，版本号和价格中的小数点仍保留。按来源筛选后再合并，不会隐藏指定来源；用户主动收藏的快照保持独立。
- 新闻列表与生活指南增加折叠的“阅读设置”，提供标准/较大/大号字号，设置在当前浏览器保留。新闻点击原文后标记已读，支持只看未读，最多保存 6000 个已读 ID。资讯收藏快照与指南收藏 ID 可一起导出 JSON，导入时合并并保留已有内容；损坏文件或不安全原文链接不会导入。没有账户或自动跨设备同步，迁移时在新设备手动导入文件。
- 首屏使用静态新闻占位、固定图标尺寸及更新状态区域；默认速览的日期和说明在 HTML 中已预留位置。后台检查提示在顶部状态区域替换显示，避免单独插入大块通知导致正文跳动。
- 游戏栏目在体育之前，接入机核、游研社、游民星空与 3DM 的 Google 新闻聚合，以及 Eurogamer RSS。最近 60 条快照加快首次打开，历史仍支持来源、日期、搜索和加载更多。
- “刷新资讯”通过 Cloudflare Worker 请求抓取和发布，完成后重新读取数据并保留当前筛选。全站共享至少 15 分钟触发间隔，已运行的任务会被复用；接口不可用时仍尝试读取 GitHub Pages 上已发布的数据。

## 我的看房

`/homes/` 是从“杭州房价”进入的个人看房本。默认条件为杭州西湖区、上城区、西溪及周边，总价 300–350 万，新房优先、二手房也可；通勤目的地为云谷和西溪园区，一个开车、一个送到地铁站。开车方向和通勤上限初始留空，可自行调整；默认方案只用于新增房源，已记录的路线不会随设置改动而变更。

- 页面首先展示公开候选：西湖、余杭、上城新房各最多 3 页；二手房读取三墩、蒋村、留下、西溪、未来科技城、闲林、仓前、良渚、勾庄及上城各自 300–350 万住宅列表前 30 条，并保留西雅图、西溪悦城、金地自在城搜索。列表校验城市、板块、价格和住宅筛选确实生效，只读取主列表。按房源编号跨页、跨来源去重；不同编号仍可能对应同一套房，页面显示挂牌条数及小区数，不称为核实套数。按预算上限、类型、区域和板块筛选；每批 12 条，同等预算和类型下先展示不同小区。覆盖是有限来源样本，不能当作全部市场；不会自动推算通勤。可一键收藏来源与当次报价，也可手动添加其他房源。
- 新房楼盘总价参考、均价乘面积的估算，与二手房单套挂牌价分别标注。新房参考金额仅写入收藏说明，取得具体房号报价前不记作挂牌价。混合物业、待售、售罄、来源状态冲突不进入默认候选。采集日期与发布日期不混用；从首次观察起保留报价和销售状态变化。分页失败只保留对应旧结果与检查日期，成功页面继续更新；跨页移动或另一个来源仍可读到的房源不会误标消失。有限列表未再出现的房源标记为“未再出现”，不推断成交。
- 每次填写价格新增一条历史，明确区分挂牌价、沟通报价和已核实成交价，保留日期与来源。卡片按记录日期取最新价格，补录较早价格不会替代较新的记录。预算提示只基于已知金额；费用留空代表未知，明确无需支付才填 0。
- 通勤分别记录开车全程（含送站）、送站绕路、地铁站、家到站、进站候车、地铁全程含换乘、出站到园区和核实依据。地铁者各段都填写后才显示合计。看房记录按次保存笔记与最多 6 张照片，照片在浏览器中压缩为最长边 1280px 的 JPEG，原图自行保留。
- 记录先写入浏览器 IndexedDB（`zrbac-home-book`）。通过私人链接连接后，同步到 `https://zacai.fun/api/homes/notebook`；共用同一私人链接的设备共用一个看房本。未连接的浏览器仍只保存本机记录。私人令牌放在 URL fragment，接收后从地址栏移除并保存在 IndexedDB，通过 Authorization 发送；服务器只保存令牌的 SHA-256 校验值。公开候选接口不包含私人笔记。
- 服务端版本号防止旧设备覆盖新记录；断网修改持久保留并在恢复网络后重试。两边都有修改时暂停上传，用户确认合并后保留两边房源，差异房源另存“导入副本”；此方式可能恢复另一边已删除的房源，合并前有说明。打开的编辑表单不会被远端更新替换。检查未变化的版本只返回版本号，避免反复下载照片。
- JSON 导出/导入保留为迁移与额外备份方式。导入先校验并确认，完全相同的房源跳过，有差异的同编号房源另存副本；已有房源不会被覆盖。当前无房源时采用备份的找房条件，否则保留当前条件。
- 存储拒绝访问时停用编辑；事务成功后才提示保存完成。多个标签页同时编辑时通过事务版本号拒绝覆盖更新的记录，并保留表单内容。备份及总记录最多 60 MB、500 套房源；每张处理后的照片最多约 1.5 MB。不能读取的备份和更高版本备份整体拒绝，不重置已有存储。
- 进入此页后按需准备离线资源；显示“已准备好，可离线记看房”后可离线打开、编辑和备份。Service Worker 升级会保留先前准备过的看房入口，记录独立保存在 IndexedDB，不随离线缓存清理而删除。

验证：`tests/test_home_finder.py` 检查来源解析、价格单位、失败保留、认证、版本冲突和数据库备份；`node --test tests/homes-core.cjs tests/sw-compat.cjs` 检查备份与合计。`tests/homes-browser.cjs` 和 `tests/home-finder-browser.cjs` 随手机检查运行，后者使用临时数据库和本地测试服务验证原有本机记录迁移、两台设备同步、离线冲突与未保存表单保护，不操作正式看房本。服务部署见 [部署说明](../deploy/homes/README.md)。

## 安装与离线阅读（PWA）

页脚“安装到桌面”在浏览器允许时唤起原生安装窗口，否则展示对应平台操作。Chrome / Edge 可从地址栏或菜单安装，iPhone / iPad 可通过 Safari 分享菜单添加到主屏幕；支持的 Mac Safari 版本可添加到程序坞。安装需要 HTTPS（本地开发允许 localhost）；安装后的名称为“资讯”，以独立窗口打开。

- `/manifest.webmanifest` 提供名称、图标、启动路径和每日速览/收藏快捷入口。PNG 图标直接由现有 SVG 站点图标导出。
- `/sw.js` 首次只缓存新闻首页与启动资源；进入小游戏、生活指南或我的看房后才分别准备其完整资源，首次联网完成后才能从该入口离线重新打开。文章、搜索和收藏使用本浏览器已保存的数据；不缓存或代理原文网站。各入口回退到各自匹配版本的缓存页面。
- 新闻 JSON、版本检查与刷新 API 不进入 Service Worker 缓存。联网时检查当前发布版本，检查期间先显示明确标记的本地数据；离线时直接阅读上次数据，恢复联网会重新检查资讯。手动刷新直接读取最新 150 条；历史在需要时继续补齐。首页完成首轮新闻请求后再注册离线资源，避免初次准备与新闻下载竞争网络；小游戏页仍立即准备。
- 首页与游戏导航优先返回已安装版本的缓存页面，避免离线启动等待网络、或在线 HTML 与旧脚本版本混用。安装阶段验证资源与 HTML 属于同一版本；不会将不存在的页面替换成新闻首页。
- 程序版本由页面模板、静态资源和 Service Worker 代码计算，另为完整离线资源计算内容版本。新闻、汇率和房价数据更新不更换程序版本；生活指南正文更新更换离线内容版本，但程序版本保持一致，新闻和小游戏不显示更新提示，指南页显示“生活指南内容有更新”。指南内容可在所有旧标签页关闭后启用，也可在指南页点击立即切换。真正的程序改动安装完成后显示“更新页面”，用户点击后切换并清理本站旧缓存，保留收藏和其他应用缓存。
- “更新页面”只在已有离线版本控制页面、且真正的新版本已安装并等待替换时出现。首次安装离线缓存经过短暂等待状态时不提示；等待版本已激活后会收回提示，包括从另一个标签页完成更新的情况。
- 离线数据保存在本机，清除浏览器存储或浏览器回收空间后可能丢失；新闻更新和原文链接需要联网。PWA 本身不需要常驻服务器，也没有额外的后台抓取任务。

完成本地构建后，可用独立安装的 Playwright 运行完整安装/离线/更新检查：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright NEWS_TEST_SITE=_site node tests/pwa-browser.cjs
```

## 离线准备与恢复

- GitHub Pages 必须开启 `https_enforced`。2026-09-26 排查发现该设置原为 false，HTTP 地址直接返回页面，因不满足安全上下文条件而无法使用 Service Worker；现已开启，线上应验证 HTTP 返回 301 到 HTTPS。页面也为 `news.zacai.fun` 提供 HTTPS 跳转兜底，本地预览不受影响。
- iPhone 从桌面图标联网打开后，需要在这个入口完成离线准备。Safari 和桌面入口不能假定共享缓存；添加图标不等于已下载离线文件。旧 HTTP 图标若仍不可用，在 Safari 普通标签页用 `https://news.zacai.fun/games/` 重新添加图标，不要求清理浏览器数据。HTTP 与 HTTPS 是不同存储来源，不能保证旧 HTTP 存档自动迁移。
- 游戏列表新增“准备离线使用／重新检查”。资讯首页不显示游戏离线状态，也不主动执行游戏缓存检查或修复。安全连接缺失、离线接口不可用、缓存缺失、下载失败和等待更新分别提示，不再统称浏览器不支持。
- Service Worker 的 `CHECK_OFFLINE` 检查完整启动资源；`PREPARE_OFFLINE` 只补缺失文件，先核对 HTML 的哈希引用再写入，禁止把新 HTML 混入旧离线版本。不会清空 localStorage、注销 worker 或删除仍能使用的文件。游戏页前台恢复或重新联网会再次检查。
- 自动修复不等于永久保存；若系统已删除整个站点数据，仍需联网重新准备。未实际取得设备日志时，不把 HTTP 入口这一可复现配置缺陷断言为用户设备的唯一原因。

本地构建后的恢复测试（独立浏览器进程关闭后断网重开、完整性检查、缺失文件修复、存档保留、不安全／无接口环境提示）：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright NEWS_TEST_SITE=_site node tests/offline-recovery-browser.cjs
```

## 旧版 Safari 兼容

Safari 15.3 缺少原生 `<dialog>` 的 `showModal()` / `close()` 和 `Object.hasOwn()`（这些在 [Safari 15.4](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/) 加入）。前者曾让游戏路由初始化中断，并让未打开的弹窗混入布局；后者曾让 Service Worker 的导航与资源读取失败。

- `compat.js` 在业务脚本之前按能力检测，仅为缺少原生弹窗方法的浏览器提供遮罩、关闭、焦点约束与 Escape 处理；`compat.css` 显式隐藏未打开的弹窗。新闻来源、安装说明和游戏弹窗共用兼容处理。兼容资源参与哈希构建、离线缓存和更新。
- Service Worker 使用 `Object.prototype.hasOwnProperty.call()` 判断路径；游戏高度使用 `visualViewport` / `innerHeight` 的像素值，并以 `100vh` 作为 CSS 回退，不依赖新视口单位。
- 已安装旧版的用户需要联网打开页面，点“更新页面”，待小游戏列表显示“已准备好，可离线玩”后再断网。无需清空已有存档。

`node --test tests/sw-compat.cjs` 在没有 `Object.hasOwn` 的独立运行环境中验证离线导航、资源和路由范围。浏览器测试可加 `NEWS_LEGACY_SAFARI=1`，移除原生弹窗方法与新接口，覆盖初始化、触屏、弹窗、存档与离线更新；PWA 测试也会移除 Service Worker 中的新接口。这是缺失功能的回归测试，不等同于 iOS 15.3.1 真机测试。

## 离线小游戏

首页右上角“小游戏”进入 `/games/`，提供打砖块（五关）、飞机大战（自动开火、敌机逐渐加速）、跳跃跑酷（二段跳）。这三款采用原生 Canvas 实现，另有蜘蛛纸牌、数独、卡牌地牢、轻量塔防、俄罗斯方块、跳一跳、消消乐和扫雷，共十一款，均不加载第三方游戏、广告、字体或网络素材。

- 游戏页使用独立满屏布局，说明收进“玩法”。三款 Canvas 游戏画面随可见视口和安全区域适配，横竖屏保持物体比例；尺寸变化时暂停并调整当前局的位置，不清空成绩。
- 手机在画面任意位置相对拖动控制挡板和飞机，按下时不会跳到手指下方；点按跑酷跳跃。电脑可用方向键 / WASD，空格或 Enter 触发动作，P / Escape 暂停。
- 切换标签、应用或离开窗口自动暂停。返回后手动继续，避免后台继续扣机会。切换游戏开始新一局，最高分保存在 `zacai-arcade-records-v1`；存储受限时仍可玩并提示无法保存。
- 蜘蛛纸牌使用 104 张牌，支持单花色、双花色、合法走法提示、发牌和最近 30 步撤销。点选牌再点目标列移动，十列牌桌自适应屏幕宽度，手机竖屏也能看全；窄屏牌面将点数和花色上下排列，横屏牌面更大；随机洗牌不保证每局有解。
- 数独有入门、标准、进阶三档（分别 42、34、28 个已知数，难度按已知数区分，不是解题技巧评级）。九道自生成唯一解模板经过保解的行列、数字和转置变换生成题面；独立求解器测试唯一性。支持候选数笔记、重复数字标红、直接填一格答案的提示、擦除、撤销和键盘操作。
- 纸牌和数独分别在 `zacai-table-spider-v1` / `zacai-table-sudoku-v1` 自动保存当前局和最近 30 步，刷新、切换游戏后可继续。新一局需在难度对话框确认后才替换；损坏存档会回退新局，存储受限时明确提示只能在当前页面内保留。
- 卡牌地牢是原创的 12 层回合卡牌探索，含四类普通敌人、三个守门人、营地、商店与装备。每回合 3 点行动、抽 5 张牌；可搭配攻击、护盾、中毒、虚弱、治疗和强化。战利品加入本局牌组，装备提供持续加成；保存随机数状态及抽牌顺序，恢复时不重新洗牌。
- 轻量塔防是一张原创的 9×9 绕行地图，共 12 波，含快敌、装甲敌与首领。箭塔单体快攻、炮塔范围伤害、冰塔减速，每塔可升至 3 级；出售返还投入金币的 70%。支持战斗中建造、暂停、两倍速，并保存波次内的敌人位置。
- 俄罗斯方块使用 10×20 棋盘，七袋随机、三个后续预览、每块一次暂存、落点提示和旋转避墙。每消除 10 行加速；手机支持按钮长按、棋盘左右滑动、向下滑动和轻点旋转。电脑用方向键、空格落到底、C 暂存、P / Escape 暂停。
- 三款新游戏分别使用 `zacai-extra-dungeon-v1`、`zacai-extra-defense-v1`、`zacai-extra-blocks-v1` 存当前局，纪录存在 `zacai-extra-records-v1`。回合操作及时保存，实时游戏每两秒、落块或波次切换、暂停和离开时保存。恢复实时游戏后需要手动继续；尺寸变化也会暂停。存档会校验，存储受限时仍可在当前页面内切换后继续，并明确提示。
- 跳一跳通过长按画面或大按钮蓄力、松手起跳；电脑支持长按空格。落台得分，连续落在圆心有额外奖励，随进度缩小台面。切换页面、旋转屏幕自动暂停，未完成的蓄力会取消；已起跳的进度可保存并继续。场景显示当前台、下一台、后续两台和最近跳过的两台，落地后镜头平滑移动；后续平台写入存档并依次成为真实目标，旧版双平台存档会保留分数和当前跳跃后补全路线。
- 消消乐使用 7×7 棋盘，支持点选或滑动交换相邻方块，横竖三连消除和连锁倍数。每关 28 步，第一关目标 1000 分，后续每关增加 250 分。无效交换不扣步，提示免费，主动重排扣 2 步；无合法移动时自动免费重排。使用红圆、黄星、绿三角、蓝方块、紫十字、橙心形区分方块，放大轮廓并去掉阴影。消除只用静态描边提示，连锁一次呈现最终棋盘，取消反复缩放和闪淡；结算完成的状态在显示更新前保存，动画中退出也不会丢失分数。
- 扫雷有入门（8×8、10 雷）、标准（9×9、14 雷）、挑战（9×12、22 雷）三档。首次翻开及周围八格安全；支持长按、右键或 F 键插旗、明确的翻开/插旗模式，以及数字格周围旗数相符后的快速翻开。随机局面不保证无需猜测。计时只统计页面在前台、获得焦点且未打开弹窗的游玩时间；挑战棋盘在高度不足时可纵向滚动。
- 这三款新游戏使用 `zacai-casual-jump-v1`、`zacai-casual-match-v1`、`zacai-casual-mines-v1` 保存进度，跳一跳最高分使用 `zacai-jump-best-v1`。读档会校验，存储受限时提示并在当前页面内保留进度。新一局先确认，扫雷可在确认框选择难度。
- 全部游戏资源在进入小游戏后预缓存，不必先分别打开每一款。页面向正在控制它的 Service Worker 查询包括桌面启动首页、两张页面、manifest、图标及全部脚本样式的完整资源是否齐全，显示“已准备好，可离线玩”后可断网使用。浏览器清理缓存后需重新联网准备。
- 更新采用现有 PWA 的“更新页面”流程，首页与已准备过的小游戏/指南页面一起校验、一起切换；首次仅看资讯不会下载另外两个入口。小游戏不会触发新闻刷新 API。

## 自动发布

`.github/workflows/news.yml` 在 `hexo` 分支相关文件更新、手动执行以及每小时第 17 分钟运行。GitHub Pages 发布方式使用 GitHub Actions。代码推送在上传发布包前运行手机首屏、杭州与民生栏目及其离线浏览、索引查找、收藏备份、旧格式兼容、PWA 更新、指南章节重试和小游戏冷启动恢复检查；按小时更新和手动刷新继续执行解析/保留规则检查，避免每次采集都重新安装浏览器。浏览器依赖锁定在 `tests/browser/package-lock.json`，可通过 `PLAYWRIGHT_MODULE=/path/to/playwright NEWS_TEST_SITE=_site node tests/check-mobile.cjs` 本地运行同一组检查。

构建从空目录生成资讯站，只发布资讯页面、小游戏、数据、RSS、站点地图和 PWA 资源。博客归档、历史文章和旧博客资源已下线，不再拉取旧博客快照；历史源码仍可从 Git 仓库中查阅。

采集时读取上次发布的 `/data/news.json`，合并去重，保留最近 30 天、最多 6000 条，历史随运行积累。达到上限时为十一个新闻分类各预留最多 545 条，分类内将预留空间分散到来源，剩余位置按最新发布时间补齐；未用满的预留空间不浪费。实际覆盖天数取决于发稿量，不保证 30 天齐全；已清理的旧数据无法凭空恢复。单来源失败时保留其历史并显示不可用状态；能正常解析的 RSS 暂无符合时间和主题条件的条目时，标为“已连接 · 暂无近期内容”，不累计连接失败，持续未新增仍由质量统计提示。网络错误、错误页面、无效 XML 与不支持的订阅格式仍标记不可用；所有来源均未取得有效条目时继续终止部署，线上保留上一个成功版本。页面分别显示最近检查时间和最新文章发布时间，超过两小时未检查会显示延迟提示。

GitHub 的计划任务不是严格实时调度，可能延迟或被跳过；公共仓库长期无活动时计划任务可能被禁用。可在 Actions 页面手动运行或重新启用。Cloudflare 每半小时检查一次停更并按条件补跑，配置见 [`ops/cloudflare/README.md`](../ops/cloudflare/README.md)；仍依赖 GitHub API 和执行队列可用，不保证严格准点。

每轮抓取的 Actions 日志包含逐来源 `SOURCE_METRIC`，记录检查时间、状态、有效条目数、新收录条目数及耗时；同样的数据写入 `news.json` 的来源状态。`newCount` 依据独立的观察历史计算：首轮建立基线，之后首次见到的有效条目计为新增，同源同日同标题的修订不重复计数。反复抓到旧文章、或文章被 6000 条归档上限清理后再次出现，都不会因此算新增。

“来源状态”提供近 7 个北京时间自然日的新增量、同标题跨源重复率、连续未新增天数，以及各日新增、重复和检查成功次数。支持分类、按新增/重复率/未新增时长排序，以及“只看需关注”。同标题按同一发布日比对，忽略空白及常见引号标点；仅 Google 新闻链接去掉末尾发布方标签，保留小数点和模型版本号。组内各源新增条目均计重复，后续发现其他源的同标题时会回填原观察日；不同标题的同一事件不计入。无新增时重复率显示横线，不显示 0%。至少新增 20 条且重复率达到 50%、连续 7 天未新增或本轮失败时标为需关注，低频官方源仍应结合发布周期判断。

质量统计从本功能上线开始积累，首轮不把现有归档冒充过去一周的统计。未新增时长以成功检查的连续观察时间为准，失败或间隔超过 3 小时后重新计时，失败次数单独记录。仅计入成功发布的采集轮次；所有来源失败时继续保留上次部署。调整某个来源的订阅地址、格式或分类会为该源重新建立基线，删除来源也会移除其统计。`sourceQualityState` 随采集器读取的完整 `/data/news.json` 保存，包含近 30 天资讯指纹和每日观察记录，独立于 6000 条正文归档；不会写入首页的小型 `latest.json`。公开汇总输出为 `/data/source-quality.<hash>.json`，只在打开来源弹窗时请求，最近查看过的同一版本可从本机缓存离线读取。汇总请求失败不影响资讯和连接状态，弹窗提供重试入口。继续使用原有 GitHub Actions 更新流程，无需新增服务器或模型 API。
